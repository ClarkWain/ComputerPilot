# v0.4.0 验证范围（2026-09-16）

本版保留截图压缩、坐标转换、输入焦点恢复、状态读取和语义批次复用。逐图形像素抽样、中断判定及 `resultVerified`、`qualityVerified`、`verifiedActions` 等字段已撤销。成功回执只说明动作执行情况，整批完成后由 Agent 查看截图判断效果。

## 已完成的验证

- 17 项非交互回归：图像编码、坐标映射、profile、语义执行、MCP、工具文档一致性、传输及参数校验。
- 两项真实桌面定向回归：连续鼠标路径；UIA 调用不移动鼠标、外部窗口抢焦点后的恢复、模态窗口阻挡报告。未据此宣称全部交互测试通过。
- 3840×2160 图像缩小为 1600×900；小图不放大；无损 WebP 像素往返一致。截图坐标与局部偏移由执行器转换。
- 真实 MCP 图片输出：1800×1400 窗口返回 1600×1244；局部返回 600×500；WebP/PNG MIME 正确。

## 绘图实验与尚未解决的问题

经典 Paint 的小尺寸原生多边形仍可能只留下部分形状。复现输入为 `tests/fixtures/paint-small-petal-known-failure.json`。增加延迟和试验性内部对角线未解决问题；这些方案没有进入最终行为。

随后使用现有连续路径语义在本地试验扫描线填充：1 像素笔触会留下白缝，重叠的 3 像素笔触改善了这一问题。12 个形状的测试约 34 秒；四花精修批次约 97 秒，随后仍需局部修补。结果经过截图目视检查，但不能证明任意图形正确或艺术质量合格。该算法目前只是本地实验，没有自动集成到 C++ 语义后端，也不随发行包提供实验画作或临时脚本。

最后一个笔触返回后，应用可能尚未完成重绘；必要时再次读取状态。程序不再以不可靠的颜色抽样判断绘图成功，也不因此中断批次。

## 使用限制

- 任意后台画布输入、任意弹窗自动处理和锁屏绘图均没有保证。UIA 直达调用取决于控件支持；前台输入由运行时恢复焦点并检查遮挡。
- 默认截图 WebP；不支持该格式的宿主需设置 `DP_IMAGE_FORMAT=png`。没有自动获知宿主图像解码能力的机制。
- 新窗口准备用于内部 `app.launch` 的匹配 profile；不会随意调整已有用户窗口。
- profile 有应用版本、语言、DPI 和布局约束，必须依据当前状态匹配。

## 复验入口

- `ctest --preset core-only -LE interactive`
- `ctest --preset core-only -R "^(native-input-routing|native-pointer-path)$"`
- `tests/paint-reliability.ps1`：创建测试 Paint 窗口，可通过 ActionsFile 指定复现输入；绘制结果需查看截图。
- `tests/capture-mcp.ps1`：对指定测试进程检查整窗/局部截图和输出格式。

交互测试必须在与目标应用相同的可交互输入桌面运行，先检查 `ready`。结果保存在 `out`，不进入发行包。
