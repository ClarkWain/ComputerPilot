# Skill 内容删改核查

后续调整说明：本记录描述上一轮恢复内容。按用户新要求，现行 Skill 已将判断脚本改成 Agent 可直接阅读的文字和 JSON 示例，仍保留环境、目标、截断、失败恢复及验收要求；list_windows 改为无参数，基础操作排在第三节，语义操作排在第四节。以下历史记录中的“检查代码/脚本示例”不代表现行 Skill 要求复制 PowerShell。

本次核对的不只是 ready:false。对照材料包括：会话中保留的 2026-09-16 详细教程（约 478 行、旧工具命名）、已打包的 47 行早期 Skill、此次修复前的 210 行四工具 Skill，以及当前客户端/C++ 实现。中间改版未单独提交，不能仅用 git diff HEAD 代表本次删减；HEAD 的首次发布 Skill 只有 20 行。

历史详细稿与修复前稿留存在 out/skill-audit/，供本地复核。本轮修改文档，不修改四工具接口或客户端行为。

## 核查结果与处理

| 内容 | 修复前情况 | 本轮处理 |
|---|---|---|
| 开始前定义完成标准 | 详细步骤被压成末尾原则 | 恢复到主流程开头，区分字段、业务、作品的完成标准 |
| 连接后判断 ready | 仍有零散文字，但主流程跳过环境判断，客户端示例没有 if | 主流程、连接例子、完整表单例子都明确判断布尔 true；false/诊断缺失时停止 |
| Open-Pilot 的真实行为 | 未说清“连接成功但环境未就绪” | 明确它不会自动抛出 ready:false；调用方必须读取初始化对象 |
| 同名 Default、能截图不等于可输入 | 主文件删掉了这条具体经验 | 恢复同桌面、会话和输入条件说明，不让截图覆盖失败诊断 |
| ready:true 的含义 | 缺少独立解释 | 恢复“只说明环境，不证明目标/动作/业务正确” |

| 只读诊断与默认激活 | 仍有零散说明，容易混用 | 明确 list_windows 与 activate:false/mode:controls；默认 get_window_state 不是后台只读 |
| 程序/skill/MCP 的区别 | 安装提示缩减，主文件缺少缺失条件处理 | 明确没有 exe/服务时报告缺少条件，不悄悄替换操作工具 |
| 持久连接和引用有效期 | 保留概述，缺少 worker 重启、窗口关闭等分支 | 恢复引用刷新表及超时后的连接处理 |
| 响应与异常控制流 | 顶层 error、isError 的说明被删减 | 恢复协议错误/工具错误区分，说明 Call-Pilot 抛异常，给 Send-Pilot 检查示例 |

| 原始截图和缩略图坐标 | 缩略图还原说明删除 | 恢复物理像素、窗口/画布原点、查看器缩放换算 |

| 焦点、遮挡、模态窗口 | 压缩成错误表里的短句 | 恢复判断表，明确阻塞窗口 ID 和新观察；不恢复手动激活工具 |
| 文本替换与输入 | 参数表仍有区别，选择理由弱化 | 恢复优先 fill_text、焦点明确后才用 type_text、快捷键与文字区分 |
| 基础批次边界 | 有“别跨未知对话框”，缺少解释 | 明确需要重新理解界面时分批；语义内部封装的弹窗可由程序处理 |
| 同色、同工具复用 | 语义部分保留，但失效条件遗漏 | 补回工具切换、用户介入、失败、弹窗后的状态确认 |
| 在应用内绘制 | “不能用导入生成图代替”删掉 | 恢复用户指定绘制方式的要求 |
| 绘图前的状态检查 | 缩放提过，但画布/图层/选区/画笔/样式具体内容删除 | 恢复大批笔画前的准备步骤，区分通用操作与适配器职责 |

| 日志与耗时 | 原稿并未完整涵盖本次 Luna 证据问题 | 新增首次运行保留关键回执，不为补日志重跑任务；区分读取耗时与模型全程 |

## 没有恢复的旧内容

以下删除符合已批准的接口改版，不应照抄历史教程：

- desktop_*、computer_*、check_environment、execute_single 等旧 MCP 名称。
- Agent 手动维护 observation/state_id，及每次输入前主动调用激活工具。
- 旧高级批次的 fromStep、before/after、独立等待工具与公开去重参数。

相应行为仍需说明：程序会自动检查/恢复，但失败要处理；基础等待使用有界观察，语义内部等待由适配器处理；输入未知时不能靠重用 RPC ID 保证不重复。四工具目前不提供独立 app.launch 或任意局部 UIA 查询，文档明确这项能力边界，不编造入口。
