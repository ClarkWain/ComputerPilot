# 原生动作回放（Replay v1）

`computer-pilot replay` 是 CLI 回放入口，运行不依赖 Python/Node。MCP 公开工具仍只有 `list_windows`、`get_window_state`、`execute_semantic`、`execute_batch`；执行器内部复用相同的 AgentApi 与独立 worker。

默认只校验，不启动应用或发送输入：

```sh
./build/core/computer-pilot replay --file examples/replays/flower-preview/replay.json
```

实际执行必须显式指定 `--mode run --output 不存在的新目录`。当前 v1 执行支持 macOS 的新建 PNG 文档；Windows 可以校验配方，但尚未提供其执行入口。发行包中的配方位于 `examples/replays/flower-preview/`，程序位于 `bin/`。

## 执行与恢复

1. 在输出目录创建之前，完整校验配方全部步骤、点坐标和按键，再检查真正执行请求的 worker。
2. 在新目录生成带唯一文件名的空白 PNG，使用指定 bundle ID 打开。只接受唯一匹配该文件名的窗口，每次准备窗口时再检查可执行文件和标题。
3. 每步获取新控件状态。新窗口启动时先等待辅助功能就绪；仅观察期间明确的 `geometry_changed` 可最多重读两次，不重放输入，也不重试锁屏/超时/引用失效。运行时解析唯一、启用、可见的控件；无法定位、断言不符、窗口切换或画布尺寸不符时停止。
4. 笔画相对当前画布原点定位，由公共输入层处理桌面与 Retina 映射。不会为了匹配旧坐标调整用户已有窗口。
5. 写入进度、最终报告和最终截图。报告记录完成的步骤/笔画，动作成功仍须验收视觉结果。

发生锁屏、权限变化、worker 重启或未知写入结果时不自动重放。部分批次的 `completed` 计入 `completedStrokes`，错误对象保留 `dispatch`、暂停与重新观察要求。传输失败按结果未知处理，不当成“尚未发送”。支持下面的显式检查点续跑；未知/部分完成的输入不自动恢复，也不排队等待解锁。

退出码：成功/校验通过为 0；执行失败为 1；参数/配方校验错误通常为 2；执行前桌面预检未就绪为 3。原有图片与新目录中的部分结果不会因为失败而被删除。

## 检查点暂停与续跑

先执行到一组笔画结束，例如小花的第 14 步（花茎和两片叶子）：

```sh
./build/core/computer-pilot replay \
  --file examples/replays/flower-preview/replay.json \
  --mode run --output out/flower-checkpoint --stop-after 14
./build/core/computer-pilot replay-resume --from out/flower-checkpoint
```

`--stop-after` 是配方中已完成步骤的绝对数量，必须位于一整组 `draw` 之后且早于最后一步。暂停成功返回退出码 0、`status:paused`，保存当前 PNG 与 `checkpoint.json`；保存完成必须由应用的 `AXEdited:false` 回读确认。检查点保存有额外的 Command+S，不计入配方步骤数。当前仅实现 macOS 执行入口。

续跑使用原运行目录中的冻结配方，重新枚举窗口并通过可执行文件、bundle ID、精确文件路径和标题辨认原文档。不会自动打开关闭的文档、创建另一张空白图或复用旧引用。校验通过后从保存的步骤位置继续，不重新画已完成的笔画；报告中的步骤数和笔画数是累计值，`steps` 仅列出本次新执行的步骤。可用 `replay-resume --from ... --stop-after 20` 再次暂停；新边界须大于已有位置。

恢复前检查：配方/文档/证据文件的 SHA-256、步骤与完整笔画数的一致性、应用已保存状态、画布大小、可观察的二态工具与颜色状态，以及当前可见画布与保存截图的逐像素一致性。文件改变、未保存、缩放/工具状态改变、画面遮挡、窗口缺失或无法唯一定位时，停止且不发送回放输入；窗口激活和观察仍会发生。校验不证明应用未暴露的内部状态一致，暂停后应保留原文档及工具、笔宽、选区现场，避免并发手动操作。

运行目录以 `.replay-active` 防止并发续跑。开始输入前，原子地将描述符改为 `in_progress`；成功暂停更新为 `ready`，全部完成改为 `complete`，完成的运行不可再次续跑。原子替换防止中途截断的 JSON 被当成有效描述符；它不提供断电或任意进程崩溃恢复保证。若在执行前已明确返回 `not_started`，且位置/笔画数没有前进，保留原 `ready` 检查点；其余失败或未知结果不重新放行旧检查点。不要通过手改状态、删除锁或覆盖证据强行重发结果未知的动作。

首版支持显式、完整笔画组边界的暂停和跨 CLI 进程续跑，不支持半条笔画恢复、任意失败动作自动重试、后台等待解锁或任意旧报告迁移。旧运行目录没有 `checkpoint.json` 时不可直接续跑。每次续跑保留独立的 `attempts/<唯一编号>/report.json`、进度和截图；原报告与既有结果保留。

## 配方结构

顶层字段：

| 字段 | 用途 |
|---|---|
| `schemaVersion` | 当前为 1 |
| `name` | 配方名称 |
| `platform` | 当前仅 `macos` |
| `application` | `bundleId` 与期望的 `executable`；不会执行 shell 文本 |
| `canvas` | 像素宽高、RGB 背景与画布控件 selector；当前要求画布原生单位与像素一一对应 |
| `strokes` | 命名笔画，每条 2..4096 个画布相对整数 `[x,y]` 点 |
| `steps` | 按顺序执行的流程，最多 512 步 |
| `provenance` | 可选的来源/参考图说明，不参与执行 |

Selector 支持精确的 `role`，加 `name` 或 `{bounds:{width,height}}`。名称是本机实际控件文字，不跨语言猜测。每个控件 ID 都来自当前观察，不写入配方。遇到截断的控件列表时不会推测未返回的控件；仅使用实际返回的匹配对象。配方还需结合界面证据与后续值断言约束高密度调色板。

步骤类型：

| type | 参数与行为 |
|---|---|
| `ensure` | `selector`、`value:0/1`；只在二态控件值不符时点击一次，并重新读取验证 |
| `click` | `selector`；优先由控件点击，或用 `offset:[x,y]` 点击该控件内的观察坐标。offset 必须有 selector.bounds 尺寸证据 |
| `assert` | `selector` 与 `value` 或 `color:[r,g,b,a]` 二选一；颜色读取 `rgb ...`，每通道容差 0.005 |
| `wait` | `selector`、`timeoutMs:1..10000`；等待弹出层等控件出现，只重新观察，不发送或重试输入 |
| `keys` | `chord`，采用与 execute_batch 相同的按键校验和别名 |
| `draw` | `strokes:[笔画名,...]`；最多 256 条为一组，持续按住左键沿点序移动，每条结束释放 |

每步必须有非空 `name`。未知类型/字段、旧会话引用、越界点、无效按键、无效颜色等会在任何输入前拒绝。单文件上限 8 MiB、单画布最多 6400 万像素、最多 128 条存储笔画及 10 万个存储点；整个配方最多派发 512 条笔画。

`reference.png` 是示例的成品对照，回放不读取或导入它。可通过 `--record 新目录` 录制 ComputerPilot 实际执行的调用，再离线导出可回放配方，见 [操作录制](RECORDING.md)。Replay v1 不包含屏幕录像、全局手动输入录制、时间轴编辑或通用应用适配；输入前仍受当前会话和目标窗口检查。

## 测试

非交互 `replay` 测试覆盖整份配方预检、迟发错误不产生早期输入、新控件 ID、动态画布原点、颜色/尺寸不匹配、锁屏部分完成、传输未知结果和不完整成功回执。`replay-cli-validation` 校验小花实例且不操作桌面。

2026-10-28 在本机解锁且授权的 macOS 中文“预览”中完成小花的 27 步、12 条笔画，保存的 1000×800 PNG 与参考图解码后的 RGB 像素完全一致，同时验收最终窗口截图。新窗口启动的 AX 就绪、重叠窗口标题定位及弹出层出现延迟在本次实测中补齐。其他界面版本仍须单独验收，结果以新文档、`report.json` 和最终截图为准。

2026-10-28 进一步完成检查点实测：同一小花文档分别执行到 14 步/3 笔、续跑到 20 步/11 笔，再通过另一个 CLI 进程完成 27 步/12 笔。每次只执行剩余步骤，最终 1000×800 PNG 的 RGB 像素与参考图完全一致，最终窗口截图也已检查。复制运行目录后，同名窗口的文件路径不匹配会在输入前被拒绝；并发锁和已完成任务再次续跑的拒绝路径也已验证，文档哈希保持不变。

本机 21 项非交互、2 项交互测试，以及接口文档和分发包检查均通过。真实“预览”通过关闭按钮的 `AXEdited` 回读确认保存状态；普通无文档窗口不保证提供该属性，不把缺失值当作已保存。
